# PR107 手機畫質修復紀錄

這份文件只記錄 PR107 的修正與驗證結果，不改動專案共用準則，也不是新的全專案驗收規則。

## 修正範圍

- 生產畫質控制器移至 `src/render/quality-controller.js`。首次降級不再鎖住恢復上限；連續四個快窗才試升一級，中速與慢速窗會中斷快窗計數。
- 試升後若再掉幀，僅暫停該級 60、120、240、最多 480 秒可見遊戲時間；重複失敗採指數退避，該級穩定成功才清除失敗記錄。試升後再通過四個快窗才視為穩定。解析度回到上限後才試開 Bloom，使用相同失敗重試規則。
- 背景間隔與恢復首幀不參與畫質量測；切回清除未完成觀察窗並重新冷卻。
- 手機遠距 NPC 只隱藏外觀，仍更新巡路、返回、互動座標與劇情掛鉤，避免原本提早返回造成角色停在目的地途中。GRK025 複核後，距離可見性改為在 pauseWhen 前更新，暫停角色靠近後可重新顯示，但路徑、劇情掛鉤仍停止，活動控制的父層隱藏不變。
- WebGL context loss 通知既有 `saveGame` 並暫停每幀更新。三秒後只顯示手動重載按鈕，不自動跳頁；正常復原會移除提示並恢復更新。存檔格式與最後安全位置規則沒有更動，未完成對話不在既有存檔格式內；作業系統直接終止分頁不保證觸發存檔事件。
- 畫布貼圖的縮小與來源重建實作沒有在這輪重構；新增測試直接執行生產 `canvasTex` 函式，涵蓋上傳釋放、clone 共用來源再建與 redraw。

## 已完成的驗證

本地修復基於 PR107 原 head `535a3e9b50504a164994d726a2d131dd1cadf724`，整合 main `e98c341fe07165dcd6a7db8c40f9b7652b948ed1`。PR106 角色識別與骨架整合保留。版本號由整合順序另行決定，本文件不指定後續版本政策。

- `npm test` 五組通過：unit 357 通過、1 略過；baozhong 80 通過；npc-costumes 9 通過；characters 270 通過；stage2 45 通過、1 略過。
- 完整測試後補上的真 DOM 按鈕測試，與 context recovery 另外三項一起重跑，4／4 通過。驗證逾時不重載、只有按鈕點擊才重載、復原移除提示。
- `npm run check`、`npm run build`、`git diff --check` 通過。
- 畫質測試直接匯入生產控制器；NPC 與畫布測試執行生產原始函式。這些是程式行為測試，不是裝置效能量測。

## 未完成與證據限制

- 本地 smoke 沒有完成：預設 Playwright 瀏覽器缺失，使用已安裝系統 Chromium 時遇到 sandbox socket 權限錯誤；正常申請執行環境權限後仍遇唯讀路徑錯誤，該路徑已停止。
- 本輪沒有 iPhone 實機 FPS、Safari 記憶體壓力、GPU 像素完整性或真實 context loss／恢復測試結果。
- PR107 原作者歷史描述中的 iPhone 閃退、卡頓、變糊及 draw call 約 2100～3400 變成 2000～2900，是原作者自報或原作者當時的量測，不是本輪修復者獨立重測。本輪沒有據此宣稱實機問題已解決，也不能只憑閃退症狀確定是記憶體不足。
- 畫布來源與 Three.js 重建路徑的靜態檢查，加上單元測試，不能替代真實 WebGL／Safari 的復原驗收。

## GRK025 複核後的追加修復

追加真 npcUpdate 暫停遠到近與不同房間回歸測試，以及生產畫質控制器的五輪退避、上限、成功重置與背景不計時測試。針對測試 15／15 通過；本節不取代後續整合樹的完整測試紀錄。
