# 美術風格規範

這份文件規定 NCCU100 畫面上所有東西「長什麼樣子」。不管你用哪一種技術做東西（直接寫 `render/kit.js`、Blender 匯出 glTF、Godot 照片重建、OpenStreetMap 灰盒、程式生成），**最後進到遊戲的畫面都要符合這裡的規則**，看起來像同一個人畫的。

- 給人：第一次動手前整份讀完，交件前用第十三節的檢查表自己核對一遍。
- 給 AI 助手：**動手建模、配色、做貼圖或寫招牌之前，先讀完這份文件**。這份文件優先於你的一般習慣；跟某個資料夾 README 衝突時，以資料夾 README 為準，並在 PR 說明。第十四節有可以直接貼給 AI 的提示詞。
- 有規則不合理、或想做新的視覺元素（新材質、新後製、新光源）：先開 Issue 討論，不要在自己的資料夾偷偷做一套。

本文件的數字都取自目前 `main` 的實際程式（`src/render/kit.js`、`src/render/post.js`、`src/world/environment/sky.js`、`src/world/building-kit.js`、`src/actors/npc.js`、各建築資料夾）。程式改了，請同步改這份文件。

## 一、一句話

**明亮、飽和、乾淨的賽璐珞卡通風，每個物件都有深藍黑色描邊，造型簡化成方塊與基本形狀；像任天堂或原神的戶外場景，但面數低到手機也跑得動。**

三個關鍵字：

1. **平塗**：顏色是一塊一塊的，明暗交給光照，不在貼圖上畫寫實陰影、髒污、反光。
2. **描邊**：物件外圍有一圈 `#2a2c4a` 深藍黑色的邊，讓輪廓清楚。
3. **簡化**：照實景的「特徵」做，不照實景的「細節」做。認得出是哪棟樓就好，不用數清楚有幾扇窗。

## 二、硬規則（違反就不能合併）

| # | 規則 | 為什麼 | 怎麼檢查 |
| --- | --- | --- | --- |
| 1 | 材質只能用 `toon()`、`basic()`，或帶 `gradientMap: GRAD` 的 `MeshToonMaterial`。不可用 `MeshStandardMaterial`、`MeshPhysicalMaterial`、`MeshPhongMaterial`、`MeshLambertMaterial` | 其他材質不吃專案的柔邊明暗與邊緣光，放在一起會像兩個遊戲 | `npm run check` 會擋 |
| 2 | 不引用外部圖片貼圖：不 import `.jpg`、`.png`、`.webp` 當貼圖，不用 `TextureLoader`。貼圖一律用 `canvasTex()` 畫 | 照片貼圖和平塗風格衝突，也會讓下載變大 | `npm run check` 會擋 |
| 3 | 參考照片只放在資料夾的 `photos/`（或 `docs/reference/`），**只給人看，不進遊戲畫面** | 同上；也避免照片版權與人像問題 | 審查時看 |
| 4 | 會擋視線、夠大的實體物件要有描邊（見第六節的表） | 描邊是這個風格最明顯的特徵 | 截圖比對 |
| 5 | 戶外不新增光源；室內最多 3 盞燈、不開陰影 | 光照統一在 `sky.js`，多開燈會破壞色調也拖慢手機 | 審查時看 |
| 6 | 重複出現的物件形狀與材質要共用（`asPrefab()`、函式外建立 geometry） | 手機效能 | 第十一節 |
| 7 | 座標單位公尺，`position.set(x, y, z)` 三個數字都要寫 | `set(x, z)` 少寫 y 會讓物件掉到地底（曾發生過） | 審查時看 |
| 8 | 文字、招牌、註解用繁體中文，全形標點，不用破折號 | 專案慣例 | 審查時看 |

## 三、目前的畫面是怎麼來的（其他技術要對齊的目標）

如果你不是用 `kit.js` 建模，要知道專案的畫面是由下面這些環節疊出來的，你的成品必須經過同樣的環節。

### 1. 卡通明暗（`render/kit.js` 的 `GRAD`）

`toon()` 建立 `MeshToonMaterial`，用一張 256 格的明暗對照表（`rampTex()`）：

- 背光面亮度固定在 **0.54**（不會全黑，陰影是「深一階的同色」）。
- 受光比例 0.40 到 0.50 之間是一條柔和但明確的明暗交界。
- 0.88 以上加一點點高光（最多 +0.05）。

所以：**你的底色就是受光面的顏色**，暗面會自動變成約一半亮度。不要自己把顏色調暗來「做陰影」。

### 2. 邊緣光（rim light）

`kit.js` 改寫了 three 的 toon shader：物件邊緣（法線和視線夾角大的地方）加一圈偏暖的亮邊，強度 0.30，朝上的面比較明顯。這是自動的，只要用 `toon()` 就有。

### 3. 描邊（`outline()`）

在物件外面套一個「反面、放大一點、純色 `#2a2c4a`」的殼（`OUT` 材質，`MeshBasicMaterial`，`BackSide`）。粗細用公尺指定，例如 `out: 0.02` 表示外擴 2 公分。

### 4. 燈光與天空（`world/environment/sky.js`）

- 天光 `HemisphereLight('#bfe0ff', '#a89a7a', 0.74)`：天空偏藍、地面偏暖褐。
- 太陽 `DirectionalLight('#fff1d4', 1.7)`：暖白，方向 `(0.72, 0.6, 0.34)`，開陰影（2048 貼圖、PCF 柔邊）。
- 天空球：頂部 `rgb(0.22, 0.52, 0.92)`，地平線 `rgb(0.81, 0.91, 0.97)`，太陽附近偏暖。
- 霧：`Fog('#cfe8f7', 140, 560)`，遠方會淡成淺藍。
- 雲：白色 toon 加一點自發光，不吃霧。

### 5. 後製（`render/post.js`）

畫面最後還會再調一次色，所以**建模時看到的顏色不是最終顏色**：

- MSAA 抗鋸齒、柔光 Bloom（亮度超過約 0.82 才會發光，戶外強度 0.42、室內 0.3）。
- 飽和度乘 **1.14**。
- 暗部偏冷（藍）、亮部偏暖（黃）。
- 輕微壓亮部、gamma 1.06、四周暗角。
- 掉幀時自動降解析度，再不行就關 Bloom。

結論：**選色要用「明亮、中高飽和」的顏色，不要用很灰很暗的顏色，也不要用接近純白的大面積（會被 Bloom 吃掉變成一片光）。** 純白 `#ffffff` 只用在小面積（線條、文字、白色傳單、小裝飾）。

### 6. 色彩空間

`THREE.ColorManagement.legacyMode = false`、輸出 sRGB。程式裡寫的 `'#rrggbb'` 都是一般看到的 sRGB 色碼；`canvasTex()` 已經把貼圖標成 sRGB。從其他軟體帶顏色進來時，用同一個 sRGB 色碼，不要自己做 gamma 轉換。

## 四、材質

### 可以用的

| 用途 | 寫法 | 說明 |
| --- | --- | --- |
| 一般實體（牆、柱、地台、家具、人物衣服） | `toon('#色碼')` | 會自動快取共用，同色同參數只建一次 |
| 有圖案的牆面、地面 | `new THREE.MeshToonMaterial({ map: canvasTex(...), gradientMap: GRAD })` | 圖案用 `canvasTex()` 畫，見第八節 |
| 招牌文字、立牌、海報等「平面資訊」 | `basic({ map, transparent: true })` | 不受光，字永遠清楚 |
| 窗戶玻璃（看不進去的） | `winMat`（`building-kit.js`，`basic` 色 `#5c7686`）或畫在牆面貼圖裡 | 窗戶不做反射、不做透明 |
| 燈泡、會亮的東西 | `toon('#fff6dc', { emissive: '#ffe6a8', emissiveIntensity: 0.6 })` | 只有「本身會發光」的東西才加 emissive |
| 半透明（候車亭玻璃、水面） | `toon('#cfe6ef', { transparent: true, opacity: 0.55 })` | 少用，會影響排序和效能 |

### 不可以用的

- `MeshStandardMaterial`、`MeshPhysicalMaterial`、`MeshPhongMaterial`、`MeshLambertMaterial`（硬規則 1）。
- 法線貼圖、粗糙度、金屬度、環境反射、AO 貼圖等寫實 PBR 參數。
- 自訂 shader：除非已在 Issue 討論過。現有的例外只有天空、水面、樹冠淡出、後製。

### 材質要共用

- `toon('#色碼')` 本身會共用，直接呼叫沒關係。
- 有貼圖的材質（`canvasTex` 加 `MeshToonMaterial` 或 `basic`）**要在函式外面建一次**，重複使用。每次呼叫都 new 會讓工具箱和靜態烘焙無法合併。

## 五、顏色

### 調色原則

1. **底色就是受光面**：選你希望太陽照到時的顏色，暗面交給 `GRAD`。
2. **明亮優先**：大面積的牆、地面，明度（HSL 的 L）大多在 55% 到 92% 之間。
3. **飽和但不刺眼**：主題色（招牌、旗子、屋頂、制服）可以很飽和；大面積的牆用低飽和的暖灰、米白。後製還會再加飽和。
4. **不用純黑**：最深的顏色用帶藍或帶紫的深色，例如 `#2a2c35`、`#2a1f2b`、`#14171f`。描邊色是 `#2a2c4a`。
5. **混凝土、石材是暖灰**：偏黃或偏綠一點點的灰，不要冷冰冰的中性灰。
6. **從照片取色後要「提亮、去髒」**：照片的顏色通常太暗太灰。取色後把明度拉高約一到兩成，飽和度略為提高，去掉陰影和髒污的顏色。
7. **一個物件通常 2 到 4 個顏色**：主色、副色、點綴色、深色細節。

## 六、描邊

### 顏色與做法

- 顏色固定 `#2a2c4a`（`kit.js` 的 `OUT`），**不可以換色**，也不要另外做描邊材質。
- 寫法：`mk(geo, mat, x, y, z, { out: 0.02 })`、`block(x, y, z, sx, sy, sz, mat, 0.03)`，或對現成網格 `outline(mesh, 0.02)`。
- 球體、膠囊等圓滑物件可以用等比放大（`npc.js` 的 `outlineU(mesh, 1.04)`）。

### 粗細（依物件大小，單位公尺）

依目前程式實際用法整理：

| 物件 | 粗細 | 例子 |
| --- | --- | --- |
| 很細的飾條、階梯每一階、地面小凸起 | 0.01 | 階梯、磚邊 |
| 細桿、小道具、家具、招牌框 | 0.015 到 0.02 | 路燈桿、欄杆、長椅、立牌 |
| 中型構件 | 0.03 | 柱子、牆墩、帳篷、攤位 |
| 建築量體、大屋簷 | 0.04 到 0.06 | 樓體、屋頂、基座 |
| 樹幹 | 0.05 | `vegetation.js` |
| 樹冠、大型圓滑物件 | 0.1 | `vegetation.js` |
| 人物身體零件 | 0.01 到 0.014，或等比放大 1.03 到 1.15 | `npc.js` |

原則：**越大的東西描邊越粗，但粗細不要超過物件最短邊的十分之一**，否則細東西會變成一團黑。

### 不加描邊的東西

- 平貼在地面上的面（`flat()`、地磚、標線、草地）。
- 貼在牆上的平面（招牌文字面、海報、牆面貼圖平面）。
- 半透明物件、水面、天空、雲、粒子特效。
- 很小、一大堆重複的細節（窗格、磁磚縫），改畫在貼圖裡。

## 七、造型與比例

### 造型

1. **抓特徵**：先列出這棟建築「讓人一眼認出來」的三到五個特徵（例如中正圖書館：抬高的基座、兩段灰石階梯、梯形正面、格柵牆、石獅），只把這些做出來，其他簡化。
2. **用基本形狀**：方塊（`block()`、`BOX`）、圓柱、圓錐、球（`SPH` 是一階二十面體）、膠囊、圓環。斜屋頂用 `building-kit.js` 的 `hipRoof()`。
3. **細節畫在貼圖上**：窗戶、窗格、磁磚、格柵、招牌底紋，用 `canvasTex()` 畫在一片平面或方塊上，不要一格一格建模。
4. **可愛化**：人物、動物、雕像用 Q 版比例（大頭、短身）。例：石獅是大頭、凸眼、捲毛。
5. **不做寫實磨損**：不做裂縫、鏽斑、污漬、苔痕的立體細節；需要「舊」的感覺時，在貼圖上用很淡的色塊表現（例：羅馬廣場的混凝土水痕）。

### 面數與分段

| 形狀 | 建議分段 |
| --- | --- |
| 細桿、燈柱 | 圓柱 6 到 8 段 |
| 一般看得到的圓柱、圓盤 | 12 到 18 段 |
| 大型圓形地標（只有少數） | 24 到 32 段 |
| 球 | 用 `SPH`（二十面體一階），或 `SphereGeometry` 不超過 16×12；人臉例外 |
| 圓環 | 6 × 18 左右 |

### 尺度

- 單位公尺。從校門面向四維堂：x 越大越右，z 越小越裡面。參考點：校門約 `(0, 10)`，噴水池約 `(0, -32)`，四維堂約 `(0, -87)`。
- **遊戲裡的水平距離大約是實際的 0.7 倍**（正門到四維堂實際約 135 公尺，遊戲 97 公尺，見 `docs/reference/README.md`）。新建築照「跟已完成建築的相對位置」放，不要直接用實際公尺換算。
- 建築本身的長寬高照「看起來的比例」做，可以為了好走、好看適度縮放，但同一區的建築彼此比例要合理。
- 階梯每階高 **0.2 公尺**（中正圖書館）。
- 人物：NPC 預設 `scale` 1.2，總高約 1.5 公尺，約 2.3 頭身。門、欄杆、長椅、桌子要以這個身高看起來合理為準。
- 步道：四維道磚面寬 10 公尺，中心線 `z = -60.2 + 0.18x`（`world/layout.js` 的 `swZ()`）。

## 八、貼圖與文字

### 一律用 `canvasTex()` 畫

```js
const wallTex = canvasTex(256, 128, (g, w, h) => {
  g.fillStyle = '#ece6d8'; g.fillRect(0, 0, w, h);          // 底色
  g.fillStyle = '#9fb3bd'; g.fillRect(9, 30, 15, 58);        // 窗玻璃
  g.fillStyle = 'rgba(255,255,255,.25)'; g.fillRect(9, 30, 15, 18);  // 反光帶
}, [4, 1]);                                                  // 重複 4 × 1 次
const wallMat = new THREE.MeshToonMaterial({ map: wallTex, gradientMap: GRAD });   // 放在函式外面
```

### 畫法規則

1. **平塗色塊為主**：`fillRect`、`arc`、簡單線條。不要用照片、不要大面積漸層。
2. **雜點可以，但要淡**：石材、磚、草地用 2 到 3 個相近色的小方點（3 像素）散佈，數量幾百個。
3. **窗戶**：玻璃色加一條半透明白色反光帶，加白色或淺色窗框。
4. **尺寸**：一般 128 或 256 見方；整面牆的正面圖最大 1024 × 512；一張貼圖用 `repeat` 重複，不要開大圖。
5. **顏色從第五節選**，跟 `toon()` 的底色一致。
6. 貼圖不畫陰影與高光（交給光照與 `GRAD`），只有窗戶反光帶例外。

### 文字與招牌

- 用 `hText()`（橫書）或 `vText()`（直書）產生貼圖，放在 `plane()` 上，材質用 `basic({ map, transparent: true })`。
- 字型：

| 用途 | 字型 |
| --- | --- |
| 一般招牌、標示、介面感的字 | `700` 或 `900` `"Noto Sans TC", sans-serif` |
| 正式的建築名稱、匾額 | `700` 或 `900` `"Noto Serif TC", "Songti TC", serif` |
| 可愛、活動感的字 | `900` `"M PLUS Rounded 1c", sans-serif` |
| 英文數字 | `700` 或 `900` `Arial, sans-serif`；校名英文可用 `Georgia, serif` |

- `hText()`、`vText()` 已加輕微下方陰影（`shadowOffsetY = 3`），不要再加粗外框或發光字。
- 字體會依玩家裝置不同，沒有中文字型時用系統字；重要的字不要依賴特殊字型才看得懂。
- 字的大小要在遊戲鏡頭距離看得清楚：招牌字高建議至少 0.3 公尺。

## 九、燈光、天空與室內

- **戶外**：不新增任何光源，不改 `sky.js`。路燈的「亮」用 emissive 燈泡表現，不放 `PointLight`。
- **室內**（獨立場景，`core/rooms.js`）：預設是 `HemisphereLight('#fff6e8', '#9a8f80', 1.0)` 加一盞 `DirectionalLight('#fff4e2', 0.8)`。自己寫 `interiorLight()` 時照同樣的組合：一盞半球光（強度約 1.0 到 1.05）加一盞方向光（強度 0.65 到 0.95），**最多 3 盞，不開陰影**（`docs/interiors.md`）。
- **另一張戶外地圖**（例如山上校區）：照山上校區的 `mapLight()`，半球光加一盞暖白太陽光，天空色 `#bfe4f6` 一類的淺藍。

## 十、植物、地面、道路

- 樹一律用 `world/vegetation.js` 的 `tree(x, z, 縮放)`、`palm()`、`banyan()`。不要自己做另一種樹，除非是有名字的特定樹種（先開 Issue）。這些已接好工具箱與擋視線淡出。
- 灌木、樹籬、花台照 `docs/prefabs.md` 的現有做法。
- 地面用 `flat()` 平面，顏色從第五節選；有紋理的地面（磚、石磚）用現有的 `brickMat()` 或同樣畫法。
- 地面層次之間要留一點高度差（例如 0.004、0.01、0.02、0.03 公尺）避免閃爍，越上層越高。

## 十一、效能預算（手機也要順）

### 一定要做

1. 形狀放在函式外面共用（`new THREE.CylinderGeometry(...)` 不要寫在迴圈或每次呼叫的函式裡）。`BOX`、`SPH` 已共用。
2. 重複的靜態物件用 `asPrefab()` 包起來（`docs/prefabs.md`）。
3. 單色、不會動的小方塊不用特別處理，場景蓋完會自動靜態烘焙（`docs/bake.md`）。**會動、會變色、之後要用名字找到的東西**，設 `name` 或 `userData.noOcc = true`，否則會被烘焙凍結。
4. 室內每個房間面積建議 60 × 60 公尺以內。

### 預算（初版建議值，之後依實測調整）

| 項目 | 建議上限（含描邊） |
| --- | --- |
| 小道具（長椅、路燈、垃圾桶） | 500 三角形 |
| 一般建築 | 15,000 三角形 |
| 大型地標建築 | 40,000 三角形 |
| 一棟建築的貼圖 | 總共不超過 6 張；單張最大 1024 × 512 |
| 一棟建築新增的不同材質 | 20 種以內（同色 `toon()` 算同一種） |
| 外部模型檔（glTF，見第十二節） | 單檔 300 KB 以內 |

描邊會讓三角形數加倍，算預算時要算進去。

### 量測

網址加 `?perf`，看 `triangles` 與 `renderCalls`（`docs/performance.md`）。走到你的建築前面，跟加之前比較，在 PR 說明寫增加了多少。

## 十二、不同技術怎麼符合同一種風格

不管用哪一種工具，**進遊戲前都要變成第四節的材質、第五節的顏色、第六節的描邊**。下面是各種做法的轉換規則。

### A. 直接寫 `render/kit.js`（標準做法）

照第四到十一節做即可。範本：`npm run new-building -- <id> <中文名>` 產生的 `index.js`，參考中正圖書館（`library`）、羅馬廣場（`roman-plaza`）。

### B. Blender 或其他 3D 軟體，匯出 glTF

建模時：

1. 單位公尺，原點放在建築底面中心，正面朝 +z。
2. 低面數，照第七節的分段數。
3. **每個材質只用一個純色（Base Color）**，不用任何貼圖、不設粗糙度金屬度。需要圖案的地方，留一個獨立的面，進遊戲後用 `canvasTex()` 貼。
4. 顏色直接用第五節的色碼（Blender 的色碼欄位輸入 sRGB 十六進位）。
5. 不匯出燈光、攝影機。
6. 匯出 `.glb`，放在自己的建築資料夾，單檔 300 KB 以內。

進遊戲時，**載入後一定要把材質全部換成 `toon()` 並加描邊**：

```js
import * as THREE from 'three';
import { GLTFLoader } from 'three/examples/jsm/loaders/GLTFLoader.js';
import { scene } from '../../../core/engine.js';
import { toon, outline } from '../../../render/kit.js';
import modelUrl from './model.glb?url';

/** 把 glTF 換成專案風格：純色 toon 材質、深藍黑描邊、投影接影。 */
function toonify(root, out = 0.03) {
  const meshes = [];
  root.traverse(o => { if (o.isMesh) meshes.push(o); });   // 先收集，避免描邊殼也被處理到
  for (const m of meshes) {
    const src = Array.isArray(m.material) ? m.material[0] : m.material;
    const color = src && src.color ? '#' + src.color.getHexString() : '#cccccc';
    m.material = m.geometry.attributes.color ? toon('#ffffff', { vertexColors: true }) : toon(color);
    m.castShadow = true; m.receiveShadow = true;
    if (out) outline(m, out);
  }
  return root;
}

function build() {
  const g = new THREE.Group(); g.position.set(X, 0, Z); scene.add(g);
  new GLTFLoader().load(modelUrl, gltf => g.add(toonify(gltf.scene)));
  boxC(X - 5, X + 5, Z - 4, Z + 4);   // 碰撞照常在程式裡登記，不從模型讀
}
```

注意：

- glTF 是**非同步載入**，會在靜態烘焙、工具箱合批與鏡頭防穿模建立之後才出現，所以不會被合併，也不會擋鏡頭。大型建築請改用方法 A，或把模型轉成程式碼資料（像方法 C 的 JSON）在 `build()` 裡同步建立。
- 描邊粗細依第六節：整棟用一個值時取 0.03 到 0.05；細部構件太細的，在 Blender 裡分成獨立物件，另外給 0.015。
- 這個做法目前專案還沒有實際例子；第一個用的人請在 PR 附截圖與 `?perf` 數字，並把經驗補進這一節。

### C. Godot、照片重建或其他引擎轉出（法學院到教育學院街區的做法）

參考 `src/world/buildings/law-education-route/README.md` 與 `scripts/style-photo-district.py`：

1. 轉出成 JSON（實例矩陣、碰撞、坡道、招牌），在 `build()` 裡同步建立，用 `InstancedMesh`。
2. **拿掉所有寫實貼圖**（`batch.pop('texture')`），每一批改成 `toon()` 純色或 `MeshToonMaterial` 加 `GRAD`。
3. **植物換成專案的樹**：透明葉片、寫實樹冠刪掉，改成和 `vegetation.js` 同造型的低多邊形球形樹冠（三色綠 `#4c9a47`、`#5cb150`、`#6bc35b`）。
4. 草地改成和原校園同色 `#86c35a`，不要另一種綠。
5. 照片原檔、人物影像不放進網頁資產。
6. 和既有建築重疊時，用設定略過（例如 `SKIP_GROUPS`），不要刪掉別人的模組。
7. 轉換腳本要能重複執行，放在 `scripts/`，並在資料夾 README 寫步驟。

### D. OpenStreetMap、GIS 或灰盒先行（山上校區的做法）

參考 `src/world/buildings/uphill-campus/README.md`：

1. 灰盒階段可以用灰色方塊，但**材質仍然用 `toon()`**，顏色用暖灰（例如 `#bdb8af`、`#c9c7c0`），地面草地用 `#6fae5c` 或 `#86c35a`。
2. 灰盒也要加描邊（建築量體 0.04 左右），這樣灰盒截圖就能看出最後的風格與比例。
3. 純建模與碰撞資料寫成不碰引擎的模組（例如 `greybox.js`），可以在 Node 測試尺寸與重疊。
4. 換成正式造型時，照方法 A 逐棟替換，顏色、描邊、貼圖照本文件。
5. OSM 資料要保留授權標示（ODbL）。

### E. 用照片或 AI 生成圖片當參考

1. 照片、AI 生成圖、Google Earth 截圖**只當參考**，放在 `photos/` 或 `docs/reference/`，不進遊戲畫面。
2. 從參考圖取色後，依第五節原則提亮、去髒，再對照調色盤選最接近的顏色。
3. 不要請 AI 產生寫實貼圖再貼上去；圖案請用 `canvasTex()` 重畫成平塗。
4. AI 生成的「概念圖」若和本文件衝突（寫實光影、無描邊、霓虹發光），以本文件為準。

### F. 程式生成（大量重複、地形、隨機擺放）

1. 隨機只用在不影響辨識的地方（樹的旋轉、雜點位置）。
2. 隨機產生的物件一樣要共用形狀材質、包 `asPrefab()`。
3. 顏色從固定的小色盤裡挑（例如樹冠三色），不要用完全隨機的 RGB。

## 十五、常見錯誤

| 錯誤 | 看起來像 | 改法 |
| --- | --- | --- |
| 用了 `MeshStandardMaterial` | 物件偏暗、沒有卡通明暗交界、沒有邊緣光，和旁邊格格不入 | 換成 `toon(色碼)` |
| 貼了照片貼圖 | 一塊寫實、模糊、有陰影的面，跟平塗的周圍不搭 | 用 `canvasTex()` 重畫成色塊 |
| 忘了描邊 | 物件輪廓糊在背景裡 | 加 `out` 參數 |
| 描邊太粗 | 細桿變成黑棒 | 不超過最短邊的十分之一 |
| 自己把顏色調暗做陰影 | 暗面變成死黑 | 底色用受光面的顏色，暗面交給 `GRAD` |
| 大面積純白 | 被 Bloom 吃掉，一片發光 | 改用 `#f4f4ee`、`#ecebe6` 等暖白 |
| `position.set(x, z)` 少寫 y | 物件埋在地底，碰撞框變成看不見的牆 | 寫成 `position.set(x, 0, z)` |
| 每次呼叫都 new 形狀或貼圖材質 | 效能變差，工具箱合不了批 | 移到函式外面共用 |
| 會動的物件沒設 `name` 或 `userData.noOcc` | 被靜態烘焙凍結，動畫不會動 | 設 `userData.noOcc = true` |
| 戶外加 `PointLight` 做路燈 | 整區色調改變、手機變慢 | 用 emissive 燈泡 |
| 自己做一種新的樹 | 樹的風格不一致，也沒有擋視線淡出 | 用 `tree()`、`palm()`、`banyan()` |
| 照實際公尺擺位置 | 跟既有建築距離不對 | 照相對位置放，水平距離約實際的 0.7 倍 |
