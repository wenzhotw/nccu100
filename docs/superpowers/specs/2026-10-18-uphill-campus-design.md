# 山上校區（自強宿舍區）設計

- 日期：2026-10-18
- 規劃負責人：andychen（山上校區）
- 範圍：`src/world/buildings/uphill-campus/`，以及安九室內所需的共用程式支援（另開 Issue）
- 配置資料：`2026-10-18-uphill-campus-layout.json`（同資料夾）

## 一、目的

把政大山上的自強宿舍區做成可以走的第二張地圖。政大人一下公車就認得出是哪裡：好漢坡、蔣公騎馬銅像、五六七八舍、安九食堂、九舍、十舍。

成功的樣子：
- 搭公車上山，在山居學習中心下車。
- 走好漢坡下到環山一道，看得到銅像和好漢坡站。
- 從擋土牆上方的路可以遠眺台北 101。
- 走外部斜坡，或穿過安九、爬旋轉樓梯，上到九舍和十舍。

## 二、目標、非目標、反目標

**目標**
1. 三層高低差和三種連接方式，都和實際一樣。
2. 核心物件的**相對位置**照實際空拍：哪棟在哪棟的哪一邊、道路從哪裡接到哪裡、哪一層在哪一層上面。尺寸和比例以「好走、好擴充」為準，可以適度縮減或調整。
3. 安九食堂有可以進去的室內（換場景），旋轉樓梯通往九舍。
4. 手機也順，維持專案明亮卡通風。

**非目標**（這一版不做）
- NPC、校園故事、成就：之後再討論。
- 宿舍房間內部、九舍和十舍的室內。
- 環山二道以南、國際大樓以北的區域。

**反目標**（技術上能動，但等於失敗）
- 相對位置跟實景對不上（例如左右顛倒、道路接錯建築），政大人認不出來。
- 走起來卡卡的：階梯塞不下、坡太陡、路太窄、迷路。
- 動到山下校園或別人的建築資料夾。
- 手機明顯掉幀。

## 三、限制（來自專案規則）

- 只改 `src/world/buildings/uphill-campus/`。共用檔案（`src/core/`、`src/systems/`、`registry.js` 等）要先開 Issue，由 wenzhotw 同意。
- 地形只用平台做高低差，最多三層。坡道用細台階加一片斜面模擬（已核可）。
- 燈光最多三盞、不開陰影；重複物件用 `InstancedMesh`；貼圖 512 以內。
- 每個 PR 只做一件事。必跑 `npm run check`、`npm test`、`npm run build`，CI 會再跑 `npm run smoke`。合併前把版本號加 0.01。
- 中文註解用繁體中文、全形標點，不用破折號。

## 四、座標與比例

- **單位與方向**：單位是公尺。x 向東，z 向南，所以北邊的 z 是負數。
- **原點**：山居學習中心下車點，也就是 `STOP`。
- **比例**：實際距離 × 0.6。
- **轉換方式**：配置資料裡的道路、建物輪廓、階梯，都是從 OpenStreetMap（ODbL 授權，需標示「© OpenStreetMap 貢獻者」）轉換來的。轉換後已和 Esri 衛星空拍核對，並依規劃負責人的指正修改。
- **地圖範圍**：x −120 到 +120、z −95 到 +100，約 240 × 195 公尺。南邊 z +65 到 +100 先保留給環山二道（第四階段），第一階段只鋪草地。範圍外的道路截斷。
- **高度縮成 0.75 倍**：水平 0.6、垂直 0.75，避免坡度變得比實際陡太多。

## 五、三層配置

| 層 | 高度 | 內容 |
| --- | --- | --- |
| 第一層 | 0 m | 環山一道、蔣公騎馬銅像圓環、好漢坡站（黑框玻璃候車亭）、好漢坡階梯下端 |
| 第二層 | +12 m | 自強五舍、六舍（北）、七八舍（南）、環繞道路、通往五六舍中間的道路、山居學習中心與下車點、安九一樓（ABC 區南側） |
| 第三層 | +15 m | 自強九舍 D 區與 ABC 區樓上、旋轉樓梯銜接建築、遮雨棚、自強十舍 A 到 D 區、服務中心、異饗食堂 |

**各道路屬於哪一層**：字母對照 `previews/road_ids.png`，OSM 編號對照配置資料。
- 第一層：T、E、S、U（環山一道與銅像圓環一帶）。
- 第二層：L、D、Y、M。
- 第三層：AA、J、N，以及 P 在台階 9 出口以北的平路段。
- 坡道：Z 是外部斜坡的起點，接著是 P 的南段，爬到台階 9 出口後變成平路。
- 不做：台階 6、10。
- 其餘道路（B、C、F、K 等）超出地圖範圍的部分截斷，不另外設計。

- **擋土牆**：在第一層和第二層之間，位置照配置資料，畫面上要看得出牆面。
- **觀景路段**：在擋土牆上方，是通往五舍和六舍中間的那段路。往西北看的遠景放台北市區天際線和 101 剪影，可以用一張背景貼圖或幾個簡單方塊做。

## 六、連接方式

1. **好漢坡**：從環山一道的好漢坡站爬上五舍。
   - 實際有兩條分支：一條到五舍西側，一條往東接到九舍西側。
   - 每階高 0.3 公尺、深 0.8 公尺，中間要有休息平台。
   - 階梯可以跟實際一樣分段折返。
2. **外部斜坡**：從山居旁的 Z 起坡，往北接 P 的南段，爬到台階 9 出口時抵達第三層，之後是平路。人和車都走這一條。
   - 好漢坡的東支線（台階 9）從好漢坡中段接到這個出口，也就是說它直接爬上第三層。
3. **安九旋轉樓梯**：在室內。從安九一樓福利社旁往上一層（約 3 公尺），出口在九舍 D 區和 ABC 區之間的一層銜接建築。

## 八、安九室內（換場景）

## 十、驗收方式

- **自動檢查**：`npm run check`、`npm test`、`npm run build` 全部通過，CI 的 `npm run smoke` 也要通過。
- **實際走一趟**：
  1. 搭公車上山，在山居下車。
  2. 走好漢坡到銅像，再走回來。
  3. 走觀景路段，看得到 101 遠景。
  4. 分別走外部斜坡和旋轉樓梯到第三層。
  5. 下山。
  - 過程中主控台不能有錯誤，背包和故事數不能消失。
- **畫面對照**：每階段截桌機和手機畫面，和 `previews/` 的空拍規劃圖對照，道路走向和建築位置要一致。
- **效能**：開 `?perf` 記錄 p95 幀時間和 render calls，在手機上實際走一次。

## 十一、交給實作者決定的事

- 樹木、路燈、欄杆的數量和擺法，以效能為優先。
- 101 遠景要用貼圖還是方塊做。

## 十三、為了好玩和好擴充做的調整（Claude 的決定）

1. **道路**：統一寬 6 公尺，人行段 3 公尺。實際上很短的轉折拉直，但接到哪棟建築、哪條路不變。
2. **建築輪廓**：建築用簡化的外框，碰撞用幾個方塊組合。碰撞不照每個凹凸做，避免玩家卡在牆角。
3. **命名錨點**：每棟建築的入口、每個地標、每個路口，都在 `layout.js` 用名字登記座標，例如 `ANCHORS['五舍入口']`。之後加 NPC、故事、互動點時用名字找位置，不用自己量座標；調整比例時，錨點跟著配置一起移動。
4. **效能**：建築、道路、階梯依材質合併成少數幾個物件，用測試鎖住物件數量上限。山上場景不會自動套用山下的靜態烘焙，所以要自己合併。
5. **找路**：路口放實體路標。另外在 Issue 請 wenzhotw 讓小地圖在山上也能畫出地圖。
6. **存檔**：系統把山上當成室內，所以自動存檔會停止。Issue 請 wenzhotw 支援在山上也能存檔；在這之前，山上不放會改變進度的內容。

## 十四、環山二道與「召喚雨神」水上溜滑梯（之後另外設計）

- 環山二道（O）要做，但縮短，放在地圖南邊預留的 z +65 到 +100 範圍內。它透過 A、G 和第一、二層相連。
- 天氣系統在山上不運作，所以雨神效果要在山上校區資料夾內自己做，或到時再請 wenzhotw 支援。
- 互動機制：玩家召喚雨神後，這條路變成水上溜滑梯。
- 怎麼觸發、從哪裡滑到哪裡、滑完到哪一層、和既有雨天系統的關係，都另開一輪設計討論。這一版只先保留路線和範圍。
